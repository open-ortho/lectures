# Supplied lecture history and material review

This archive makes 15 supplied historical lecture records discoverable through
[event pages](../index.html) and a [sanitized inventory](history.json). The source
attribution is **Organizer-supplied history**. This is a selected history, not exhaustive:
it does not claim to list every lecture or every presenter. Private correspondence,
contact lists, message/calendar identifiers and private logistics are not published.

Delivery and material identity are separate questions. Six presentations are
confirmed; nine records establish scheduling only. **Scheduled; delivery unconfirmed**
is a historical uncertainty label, not an invitation to a future session. A high
material-match confidence does not confirm that a scheduled session took place.

All material links lead to evolving current slides or a course index. No record
identifies an immutable historical slide snapshot. Candidate titles in the table
name the current material, not necessarily the event's original title or contents.
Descriptive event titles are editorial labels, explicitly marked on their pages.

## Public inventory fields

`history.json` is a manually maintained, sanitized inventory, not a raw source copy.
Its top-level `source` records the attribution above. Each record uses these fields:

| Field | Meaning |
| --- | --- |
| `source_id` | Stable public event identifier; not an email or calendar identifier |
| `date` | Recorded ISO date (`YYYY-MM-DD`) or planned month (`YYYY-MM`) without an invented day; also the date sort key |
| `date_precision` | `day` or `month`; sorting does not add precision |
| `date_note` | Qualification of the date, especially Ferrara's planned month |
| `institution` | Institution associated with the record, not a hosting or employment claim |
| `audience` | Recorded intended audience; does not establish attendance |
| `display_title` | Established event title, marked descriptive label, or the existing current published title |
| `title_status` | `established`, `descriptive`, or `current published title`; a descriptive label is not an authenticated original title |
| `delivery_status` | `Presented` only for confirmed delivery; otherwise `Scheduled; delivery unconfirmed` |
| `material_path` | Repository-relative path to current candidate material or the referenced course |
| `material_status` | `provisional` guess, `course-family` explicit course reference without module identity, or `confirmed` organizer-confirmed module association |
| `confidence` | `low`, `medium` or `high` confidence in the material association only, not delivery or historical-version identity |
| `rationale` | Why the association is plausible or known, with its limitations |
| `event_path` | Repository-relative path to the dated event page; existing events are reused |

## Maintain a historical record

The maintainer edits this archive manually; there is no generator or automatic
status update. Keep public facts independent from material hypotheses.

1. Correct the selected record in [history.json](history.json), preserving its
   stable identifier and the precision of its recorded date. Use only sanitized,
   organizer-supplied event facts. Do not publish correspondence or private logistics.
2. Update that record's linked event page and its row in the root **Events** table
   in [index.html](../index.html). Keep the two October cohorts as separate URLs.
   New historical pages share [event.css](event.css), the existing Toni Magni
   portrait and this guide; they do not need duplicative per-event READMEs.
3. Update this review table and any affected uncertainty notes with the corrected
   material status, confidence and rationale. A confirmed delivery does not by
   itself confirm material use. If only the course is known, link its index rather
   than inventing a module assignment. Do not add an unverified event to a deck's
   confirmed presentation history.
4. Preserve the **View candidate slides** label and provisional-version warning
   while a match remains a guess. Use **View referenced course** for course-family
   references. Keep the no-snapshot qualification even after a module is confirmed
   unless a specific delivered version is established separately.
5. Run `python3 -m unittest discover -s tests -v` from the repository root.
   Preview the catalog and changed pages with `make serve` using the access and
   desktop/mobile checks in [the shared event guide](README.md#preview-and-check).
   Passing structural tests is not factual approval or a rendered-layout review.

For new upcoming events, use [the normal event procedure](README.md#add-or-correct-an-event)
instead of treating historical uncertainty as a future schedule.
