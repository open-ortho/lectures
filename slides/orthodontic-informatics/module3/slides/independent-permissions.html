7–15 · Who is adapting?

  • Filter the tools: remove or limit operations the harness—the software managing model/tool interaction—can request through this route, such as omitting send.
  • Restrict the account: give the agent its own identity with service-enforced limits on resources and actions, such as reading only permitted mailboxes.
  • My actual workflow: filtered/modified MCP tool servers plus agents' own independently restricted accounts; the agent does not inherit all my human access.
  • Background contrast: the earlier diagram illustrates a filtered tool path using a human account; that is not the account arrangement described here.
  • Both controls: a filter does not constrain the account through other clients; a restricted account may still allow more tool operations than this task needs.
  • Enforcement: the service must reject a forbidden resource request even if the model asks convincingly; neither layer alone guarantees safe output.
