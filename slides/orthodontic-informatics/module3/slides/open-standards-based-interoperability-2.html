27–39 · Choose an exchange contract

  • Version: ask which FHIR (Fast Healthcare Interoperability Resources) edition both products implement; a matching name alone leaves edition differences unresolved.
  • Profile: narrows a standard's choices for a use case—for example, requiring a particular field. Profile usage differs across standards communities.
  • Implementation guide: brings profiles, agreed usage rules and examples together so teams implement the same exchange rather than make incompatible local choices.
  • Terminology: agreed codes and meanings let both products interpret the same observation; check measurement units as well as readable labels.
  • Supported operations: specify which records and actions actually work; reading a record does not imply permission or capability to write one.
  • Case evidence: ask whether P-18's unit, visit link and original source survive under those rules; compatible labels alone do not prove it.
