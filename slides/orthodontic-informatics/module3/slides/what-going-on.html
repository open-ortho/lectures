From clinical need to shared rules

  1. Clinicians describe the use case and failure conditions.
  2. Standards experts check what existing rules cover—and where gaps remain.
  3. Teams develop corrections, profiles or implementation guidance.
  4. Implementers test, report problems and refine the agreement.

DICOM, HL7 and IHE are communities to engage—not dates to memorize.

39–49 · Shape and test exchange

  • Clinical use case: describe who needs which information for what task, plus unacceptable outcomes such as a wrong-visit measurement.
  • Gap check: standards experts ask whether existing exchange rules already meet that need and identify missing or ambiguous parts.
  • Corrections and guidance: a missing capability may need a correction/extension; unclear use may need a profile (selected constraints) or clearer implementation instructions.
  • Test and refine: implementers try the agreement, report mismatches and revise it; this is iterative, not one universal approval sequence.
  • DICOM and HL7: imaging and wider clinical-exchange standards communities need clinical input about real workflows, not memorized launch dates.
  • IHE: Integrating the Healthcare Enterprise develops profiles coordinating existing standards for defined workflows; attending an event does not make a draft an established standard.
