Email: a person uses a mail client

The human uses the client; the mail service checks the human account.

MBOX: mailbox file format. IMAP: protocol for accessing mail.
Conceptual architecture—not Gmail’s literal storage or webmail implementation.

7–15 · Who is adapting?

Read left to right: stored mail, service, client, human with a laptop. MBOX is a file format holding mailbox messages. Internet Message Access Protocol (IMAP) lets a client access and manage messages and folders through a service. The store-to-service arrow shows mailbox data supplied to the service; the client-to-service arrow means the client requests operations. Results return to the client. The two-way human connection represents interaction with the mail client, not a separate mailbox connection.

This is an illustrative architecture, not a claim about Gmail storage or its internal webmail protocol. Providers need not use MBOX, and webmail may use other interfaces. Gmail is only a familiar example of a webmail reader; Thunderbird and Apple Mail are familiar mail applications that can use IMAP. Do not teach this as Gmail’s literal implementation.

The dashed line sits just right of IMAP, across the client-facing connection. The mail client authenticates with the human account; the IMAP service enforces the account’s mailbox permissions. Credentials can be a configured secret or token, not necessarily a typed password. The line highlights mailbox authentication only, not all security boundaries. No sending transport is shown.
