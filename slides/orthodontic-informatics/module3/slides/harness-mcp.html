How does the model reach a tool?

Model ↔ harness ↔ selected email tools ↔ email service

Harness
The surrounding software that connects the model to tools and manages their interaction.
Model Context Protocol (MCP)
A common protocol through which servers expose tools to the harness.

A tool connection does not supply clinical meaning or grant permission by itself.

7–15 · Who is adapting?

  • Harness: the surrounding application gives the model tool descriptions, handles requests, obtains results and continues the interaction—not another model.
  • Model ↔ tools: the model proposes a call; the harness executes permitted calls. The arrows show interaction, not model-held credentials or direct networking.
  • Model Context Protocol (MCP): a common way for servers to expose tools and return results to the harness.
  • Selected email tools: my filtered/modified servers offer chosen operations; a server is software providing operations, not necessarily a separate physical machine.
  • Email service: a save-draft tool stores the reply there; text generated by the model alone has not saved anything in the mailbox.
  • Clinical meaning: a tool connection does not reconcile patient identity, define a diagnosis or grant access; service permissions still apply.
