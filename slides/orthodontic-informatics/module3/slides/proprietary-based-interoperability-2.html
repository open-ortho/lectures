27–39 · Choose an exchange contract

  • Vendor agreement: API documentation explains requests; mapping documentation explains how one product's fields become the other's—not just that a connection exists.
  • Standards agreement: name the edition, profiles (constraints on choices) and supported operations (actions); a shared label leaves these open.
  • Maintenance owner: name who fixes the bridge/API or standards implementation/mapping when either product changes; shared rules do not maintain software themselves.
  • Regression tests: rerun known exchanges after changes to detect lost behavior—for example, a source link disappearing while the summary stays readable.
  • Repeated work and cost: shared specifications may reduce custom translation, but mismatched versions or unsupported fields still create work; lower total cost is not guaranteed.
  • Stable upgrades: ask for test evidence and an accountable owner on both paths, not an assurance based on proprietary or standards branding.
