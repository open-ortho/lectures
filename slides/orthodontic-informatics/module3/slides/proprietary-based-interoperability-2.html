27–39 · Choose an exchange contract

  • Roles and scope: provider exposes records/API; consumer builds the connecting software. Effort labels illustrate the same agreed exchange, not measured costs or universal rankings.
  • Design · provider: custom APIs require a new exchange contract; standards supply it, with limited customization/extensions for unmet needs.
  • Design · consumer: custom connections need pair-specific bridge designs; standards reuse the shared exchange design, not invent another one.
  • Implementation · provider: generic API tools help, but the bespoke contract still needs implementation; standards can reuse available implementations/libraries.
  • Implementation · consumer: custom bridges are pair-specific; standards can reuse implementations/libraries where available—not for every standard or language.
  • Maintenance · provider: routine upkeep remains: own API on the custom path; shared implementation and version updates on the standards path, including extensions.
  • Maintenance · consumer: many changing custom bridges multiply upkeep; a reusable standards implementation still needs updates and newly required features.
  • Reuse has conditions: each product still needs mapping, configuration and testing; compatible versions, profiles and operations matter. Extensions also need maintenance.
