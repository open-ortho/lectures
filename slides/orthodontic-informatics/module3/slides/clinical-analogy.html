15–27 · Make context reusable

  • Proposed analogy: apply the working email example to clinical records; this is not a deployed clinical integration.
  • Now: a clinician copies screenshots from product A and re-enters information in B; each transfer repeats manual work and context explanation.
  • API: application programming interface—a software route for B to request records from A and return results, rather than a person copying them.
  • Reusable records/results: carry patient and encounter (visit) links and sources; returned results need review before authorized saving.
  • Independent access: each consuming system needs its own configured identity and permissions, not a borrowed full-access clinician login.
  • Not sufficient alone: an API does not ensure matching meaning or safety; ask what happens if the right image belongs to the wrong visit.
  • Reveal and bridge: Now, then What it could be; next identify the context that must travel with the records.
