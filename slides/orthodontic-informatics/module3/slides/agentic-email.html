7–15 · Who is adapting?

Compare with the previous slide: storage, IMAP, the dashed authentication boundary and the human have not moved. MBOX is an illustrative mailbox file format, not a claim about every provider. IMAP is the Internet Message Access Protocol for reading and managing mail, including storing drafts; no sending transport is shown. The MCP server is now the IMAP client. It translates selected email tool requests into mail-service operations.

The human controls the harness, not the model directly. The outer Harness box contains the inner Model box as a conceptual software relationship, not a claim that model inference runs locally. Model Context Protocol (MCP) is the protocol by which the server exposes tools to the harness. The two-way model-to-MCP arrow shows logical tool requests and returned results, not a direct model network connection. The harness executes permitted tool calls, contacts the MCP server and returns results to the model. The human’s two-way connection terminates on the outer harness. The store-to-service arrow shows mailbox data supplied to the service; the MCP-to-IMAP arrow shows requests, with responses returning. These are conceptual relationships rather than a full packet trace.

In this diagram the MCP server authenticates with the human’s email account at the client-facing IMAP edge. Credentials are configured outside the model; the model does not receive raw credentials. The service enforces the human account’s existing resource-side permissions. The MCP server’s tool filtering exposes selected operations: read mail, compose text and save drafts, with no send tool. The filter limits this tool path, not the account itself; the underlying human account retains its real permissions, including access through other clients. This is not equivalent to independent least-privilege account permissions.

An alternative dedicated agent account may be restricted or unrestricted depending on its configured permissions. Agent ownership alone does not establish restricted access. A limited tool interface and genuinely restricted account permissions are complementary controls. This diagram illustrates the human-account alternative, not a change to the presenter’s personal account setup.

The highlighted dashed line is mailbox authentication only, not an all-security diagram. There may be additional authentication between harness and MCP server, and other security controls not drawn. A tool connection is not a permission or safety guarantee. Next unpack the roles of harness and MCP, then contrast the two complementary permission controls.
