MCP: Model Context Protocol. The harness is software connecting the model and tools.

7–15 · Who is adapting?

  • Same mailbox: MBOX is illustrative message storage; IMAP (Internet Message Access Protocol) serves mailbox data, including saved drafts—not sending.
  • Human and harness: The human controls the harness, not the model directly. This surrounding software manages model/tool interaction; nesting does not imply local inference.
  • MCP server: Model Context Protocol exposes selected tools: Read retrieves mail, Compose prepares reply text, Save drafts stores it; No send tool is offered.
  • Tool requests / results: the two-way arrow is logical, not a direct model network connection; the harness executes calls and returns results.
  • Mailbox requests: the MCP server acts as the IMAP client; it requests service operations and receives responses backed by the stored mail.
  • Authentication: The MCP server authenticates to the mail service; here it uses the human account. The model does not receive raw credentials.
  • Path versus account: with tool filtering, the filter limits this tool path, not the account itself; not equivalent to independent least-privilege account permissions—rights limited to the task.
  • Account enforcement: the service enforces resource-side permissions—actual account rights, including through other clients; a separate agent account can be restricted or unrestricted depending on configuration.
  • Diagram boundary: this illustrates the human-account alternative, not my personal setup; additional authentication may protect harness-to-server access. No tool connection alone guarantees safety.
